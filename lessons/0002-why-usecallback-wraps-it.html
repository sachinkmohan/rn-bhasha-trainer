Lesson 0002 · Callbacks

Why useCallback Wraps It

← Lesson 1: What Is a Callback? established the core idea: a callback is a function you hand to something else, which calls it later, at a moment of its choosing. This lesson is about a new wrinkle: how does the "something else" know when to call your function again versus reuse what it already has?

The code that raised the question

You just added this to app/mastered-words.tsx:

useFocusEffect(
  useCallback(() => {
    getMasteredWords();
  }, [getMasteredWords]),
);

useFocusEffect is a callback receiver, same shape as the callback props from Lesson 1 — you hand it a function, it decides when to call it (specifically: whenever this screen becomes the focused one). But notice it's not just handed a plain function — that function is wrapped in useCallback first. Why the extra layer?

The problem: functions are recreated every render

Every time a component function runs again (a re-render), any () => {} written directly inside it is a brand new function object in memory — even if the code inside looks byte-for-byte identical to the previous render's version. JavaScript doesn't consider two structurally identical functions "the same"; it compares them by reference.

const a = () => {};
const b = () => {};
console.log(a === b); // false — different objects, identical code

useFocusEffect needs to know whether the function you gave it this render is "the same one as last time" or "a new one." It figures that out the same way useEffect does: by comparing references. If you hand it a fresh function reference every render (because you never wrapped it), it looks new every single time — so the effect re-runs far more often than you want.

Primary source: React Navigation docs — useFocusEffect — "it's important to wrap the callback in useCallback to avoid running the effect too often."

What useCallback actually gives you

useCallback(fn, deps) doesn't change what fn does. It changes whether React hands back the same reference across renders. As long as everything in deps is unchanged since last render, useCallback returns the exact same function object it returned before — not a new one. That stable reference is what lets useFocusEffect correctly conclude "nothing changed, no need to re-run."

The key move: useCallback is a promise about identity, not a promise about behavior. The function still does the same thing either way — wrapping it only affects whether === comparisons across renders say "same" or "different."

The classic example, simplified

useFocusEffect is one consumer of a stable reference, but it's not the example most people learn useCallback from. The textbook case (react.dev uses a checkout-form version — this is the same mechanism, stripped to the smallest possible shape) is: a component with two unrelated pieces of state, where changing one shouldn't cause a child to re-render.

function Screen() {
  const [count, setCount] = useState(0);
  const [text, setText] = useState("");

  // Without useCallback: a NEW function object every render of Screen
  const handleClick = () => setCount(count + 1);

  return (
    <>
      {/* typing here re-renders Screen — count didn't change, only text did */}
      <TextInput value={text} onChangeText={setText} />
      <ClickButton onClick={handleClick} />
    </>
  );
}

const ClickButton = memo(function ClickButton({ onClick }) {
  console.log("ClickButton rendered"); // watch this fire on every keystroke
  return <Pressable onPress={onClick}><Text>Click me</Text></Pressable>;
});

ClickButton is wrapped in memo, which tells React "skip re-rendering me if my props are all the same as last time." But every keystroke in the text field re-renders Screen — and every render of Screen creates a brand-new handleClick function. So onClick never looks unchanged to memo, and ClickButton re-renders on every keystroke, even though nothing about clicking changed at all.

const handleClick = useCallback(() => setCount(count + 1), [count]);
// stable unless count itself changes — typing in the text field no longer
// creates a new handleClick, so ClickButton stops re-rendering on keystrokes
Primary source: react.dev — useCallback: Skipping re-rendering of components (this example is a simplified version of the same mechanism react.dev documents with a checkout-form example)

Same underlying mechanism as useFocusEffect, different receiver: there, useFocusEffect was the thing comparing references to decide "should I re-run this?" Here, memo is the thing comparing references to decide "should I re-render this?" useCallback's job is identical in both: give whoever's comparing a stable reference to compare against.

Trace it through your own code

Your useCallback has one dependency: getMasteredWords. Is that stable across renders of MasteredWordsScreen? Look at hooks/useMasteredWords.ts:

const getMasteredWords = useCallback(async () => {
  ...
}, []);

getMasteredWords is itself wrapped in useCallback with an empty dependency array — meaning it never changes reference for the lifetime of the hook. That's what makes the whole chain stable: getMasteredWords never changes → your useCallback's dependency never changes → your wrapped function never changes → useFocusEffect only re-runs it when the screen actually re-focuses, not on every render.
