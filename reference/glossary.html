Glossary — Callbacks & Hooks

Compressed definitions, in the order you'll meet them. Every lesson uses these exact terms — if a lesson's wording ever drifts from this page, this page wins.

Callback

A function passed into another piece of code as an argument, to be invoked later by that code — not by you, and not necessarily right away. See Lesson 1.

Callback prop

A callback that travels through a React component's props instead of a plain function argument. The component receiving it decides when to call it; the component (or screen) that passed it decides what happens when it's called.

Hook memory cell

Each component instance gets a private, ordered list of storage slots that survives across that instance's re-renders. Every hook call (useState, useCallback, useRef, etc.) claims the next slot in that list, in the exact order the hooks are called. This is why hooks can't be called conditionally — React identifies "which slot is this" by call order alone. See Lesson 3.

Reference equality

JavaScript's rule that two functions (or objects/arrays) are only ===-equal if they're the literal same object in memory — not if their code/contents merely look identical. () => {} written twice creates two unequal objects.

Memoization

Reusing a previously-computed value instead of recomputing it, when the inputs haven't changed. useCallback and useMemo are React's memoization hooks — they reuse the last function/value if their dependency array is unchanged.

useCallback

A hook that returns a stable function reference across renders, as long as its dependency array hasn't changed. Doesn't change what the function does — only whether repeated renders get the same object or a new one. See Lesson 2.
